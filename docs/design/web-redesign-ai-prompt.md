# WARA 웹 전체 재디자인 — AI 비주얼 목업 프롬프트

> 이 문서는 **비주얼 목업/이미지를 생성하는 AI**(예: v0 비주얼 모드, Figma AI, Midjourney/이미지 생성, Claude 비주얼 디자인 등)에게 그대로 입력해, WARA 웹 앱의 **모든 화면을 완전히 새로운 비주얼 아이덴티티로** 다시 디자인하기 위한 프롬프트입니다.
>
> 코드 산출물이 아니라 **고해상도 화면 목업(mockup)** 을 만드는 것이 목표입니다.

---

## 0. 이 문서 사용법

- **전체를 한 번에 줄 때:** §1~§4(맥락·미션·아이덴티티·글로벌 규칙) + §8-(a) 마스터 프롬프트를 통째로 입력 → AI가 먼저 새 디자인 시스템을 정의하고, 그 시스템으로 전 화면을 그리게 한다.
- **화면별로 끊어 줄 때:** §3에서 확정된 디자인 시스템 요약 + §8-(b) 템플릿에 §5의 해당 화면 명세를 끼워서 한 화면씩 생성한다.
- **출력 기대치:**
  - 모바일 프레임 **390 × 844** 기준 (대응 범위 360×800 ~ 430×932)의 고피델리티 목업.
  - 화면당 **핵심 상태 변형**을 함께 (예: 기본 / 빈 상태 / 로딩 / 에러 / 권한 없음 등 해당 화면에 필요한 것).
  - 실제 **한국어 더미 카피**로 채울 것 (lorem ipsum 금지).

> **중요:** AI는 §3의 "새 디자인 시스템"을 **먼저 한 번 정의**한 뒤, 모든 화면에서 그 시스템을 **일관되게** 적용해야 한다. 화면마다 색/폰트/형태가 달라지면 실패한 결과물이다.

## 1. 제품 개요 (맥락)

**WARA는 모바일 우선 디지털 초대장 서비스다.** 사용자는 모임(생일·집들이·돌잔치·동창회·소규모 파티 등)을 위한 초대장을 만들어 공유하고, 받은 사람은 참석 여부(RSVP)를 응답한다. 모임이 끝나면 같은 공간에서 사진과 댓글로 **추억 앨범**이 된다.

**두 핵심 사용자**
- **호스트(Host):** 초대장을 만들고, 참석 현황을 관리하고, 공지/사진을 남긴다.
- **게스트(Guest):** 초대장을 받아 날짜·장소를 확인하고, RSVP하고, 댓글·사진으로 참여한다.

**감정 목표:** 받는 순간의 **설렘**, 호스트의 **따뜻한 환대**, 그리고 무엇보다 **쉬움**(누구나 1분 안에 이해하고 응답).

**핵심 과업(Jobs To Be Done)**
1. 예쁜 초대장을 빠르게 만든다.
2. 날짜·장소를 한눈에 파악한다.
3. RSVP를 손쉽게 한다.
4. 호스트가 참석자를 쉽게 관리한다.
5. 모임 후 사진·댓글을 자연스럽게 남긴다.

**최우선 원칙(디자인보다 위):**
> 예쁜 장식보다, **초대받은 사람이 화면을 보고 바로 이해하고 행동할 수 있는 것**이 우선이다. 다음 질문에 모두 "예"여야 좋은 화면이다 — (1) 무엇을 해야 하는지 명확한가 (2) 날짜·장소가 바로 보이는가 (3) RSVP가 쉬운가 (4) 호스트가 참석자를 쉽게 관리하는가 (5) 사진·댓글을 자연스럽게 남기는가 (6) WARA만의 정체성이 느껴지는가.

## 2. 재디자인 미션 & 원칙

### 미션
WARA 웹의 **모든 화면을 완전히 새로운 비주얼 아이덴티티로** 다시 디자인한다. 기존 디자인(레트로·Y2K·파스텔)은 **버리고**, 새로운 톤·컬러·타이포·형태 언어를 세운다. 단, 위 §1의 **정보 구조와 UX 우선순위는 그대로 계승**한다 — 즉 "보기 좋게"가 아니라 "쓰기 좋게 + 새롭게".

### "좋은 디자인"의 기준
- **한 화면 = 하나의 주요 행동.** Primary 액션은 화면당 1개. 나머지는 보조 위계로.
- **날짜·장소·CTA**는 스크롤 없이 즉시 인지된다.
- **컴포넌트 일관성** — 같은 요소(버튼/카드/배지/입력)는 어디서나 같은 모양.
- **위계가 분명한 타이포** — 제목/본문/보조정보가 크기·굵기·색으로 구분.
- **접근성** — 명확한 대비, 충분한 터치 영역, 사람이 읽는 문구.

### 절대 불변 제약 (새 아이덴티티와 무관하게 항상 지킨다)
- **모바일 프레임 우선** — 390×844 세로 화면 기준으로 디자인.
- **한국어 UI** — 모든 텍스트는 자연스러운 한국어. 짧고 쉬운 마이크로카피.
- **라이트 모드 기본** (다크 모드는 이번 범위 밖).
- **Safe Area** — 상단 44px, 하단 34px, 좌우 기본 패딩 20px(좁은 화면 16px).
- **최소 터치 타깃 44px**, **본문 최소 14px**(권장 16px), 버튼 높이 44px 이상.
- **하단 고정 CTA** 패턴을 기본 액션 배치로 사용(화면 성격에 따라).

## 3. 새 비주얼 아이덴티티 브리프 (가장 중요 — 먼저 시스템부터 정의)

> AI는 화면을 그리기 **전에**, 아래 항목을 모두 채운 **하나의 일관된 새 디자인 시스템**을 먼저 정의·제시하라. 그런 다음 모든 화면에 그 시스템을 적용하라.

### 3-1. 먼저 결정할 무드 (택1, 끝까지 일관 적용)
아래는 **출발점 영감**이다. 아래 방향을 골라 끝까지 일관되게 밀고 간다(혹은 이에 준하는 명확한 단일 컨셉을 새로 세워도 좋다). **여러 무드를 섞지 말 것.**

| 무드 후보 | 느낌 | 컬러 성향 | 타이포 성향 | 형태 |
|---|---|---|---|---|
| **A. 차분한 에디토리얼** | 잡지·청첩장 같은 절제·고급감 | 뉴트럴 베이스 + 잉크 한 컬러 포인트, 낮은 채도 | 세리프 디스플레이 + 깔끔한 산세리프 본문 | 적은 radius, 넓은 여백, 그리드 |
| **B. 선명한 네오-팝** | 또렷하고 경쾌·현대적 | 화이트 베이스 + 비비드 1~2색, 높은 대비 | 굵은 지오메트릭 산세리프 | 또렷한 카드, 굵은 보더 또는 컬러 블록 |
| **C. 포근한 오가닉** | 따뜻하고 부드러운 손맛 | 크림·샌드 베이스 + 어스톤/뮤트 포인트 | 라운드 휴머니스트 산세리프 | 큰 radius, 부드러운 그림자, 유기적 형태 |

### 3-2. 정의할 디자인 시스템 항목 (체크리스트)
AI는 고른 무드를 바탕으로 아래를 **구체값으로** 확정해 먼저 보여준다.

- **브랜드 퍼스낼리티 키워드** 3~5개 (예: "환대하는 / 또렷한 / 정돈된").
- **컬러 시스템**
  - 배경/표면(라이트), 텍스트(주/보조/비활성), 보더.
  - **주조색(Primary)** 1 + **보조색(Secondary)** 1 + **강조색(Accent)** 1.
  - 시맨틱: 성공/경고/위험/정보.
  - **규칙: 한 화면에서 강한 포인트 컬러는 최대 2개.** 삭제·위험은 반드시 위험색(주조색으로 쓰지 말 것).
- **타이포그래피**
  - 디스플레이/제목용 폰트 + 본문용 폰트 페어링(웹폰트 가정).
  - 타입 스케일: Display / Heading 1~3 / Title / Body 1~3 / Caption / Button — 크기·줄높이·굵기 명시.
- **형태 언어** — 카드/버튼/입력의 radius, 그리드, 모서리 처리.
- **깊이 표현** — 그림자 vs 보더 vs 컬러 블록 중 무엇으로 위계를 줄지(한 방식으로 통일 권장).
- **아이코노그래피** — 라인/솔리드/듀오톤 등 한 스타일.
- **일러스트/스티커/장식** — 쓸지 말지, 쓴다면 톤(과하지 않게, 화면당 1~2개).
- **사진 트리트먼트** — 라운드/비율/오버레이/필터 규칙(초대장 커버·앨범에 중요).
- **모션 의도** — 목업이라도 주요 전이·강조(예: CTA 등장, 카드 진입)를 주석으로 표시.

### 3-3. 산출 순서
1) 위 시스템을 한 장의 **스타일 가이드/디자인 시스템 보드**로 먼저 출력.
2) 그 다음 §5의 화면들을 시스템에 맞춰 순서대로 출력.

## 4. 글로벌 UI 규칙 (전 화면 공통 셸)

### 화면 구조 (표준 레이아웃)
```
┌─ Status / Safe Area (상단 44px)
├─ Top App Bar        (뒤로가기 / 타이틀 / 액션 아이콘)
├─ Content Area       (Section · Card · Form · List 조합, 좌우 패딩 20px)
│     · 섹션 간 간격 넉넉히 (≈32px)
│     · 카드 내부 패딩 16~20px
├─ Sticky CTA         (하단 고정 주요 버튼) — 필요한 화면만
└─ Bottom Navigation  (홈/목록/알림/프로필 등) — 최상위 화면만
   └─ Bottom Safe Area (34px)
```

### 공통 컴포넌트 표준 (전 화면에서 동일 모양)
- **버튼:** Primary(주요 액션 1개) / Secondary(보조) / Ghost(텍스트) / Danger(삭제·위험). 상태: 기본·hover·pressed·disabled·loading.
- **입력/폼:** 라벨 + 입력 + 도움말/에러. 에러는 필드 바로 아래 빨강 텍스트. 입력 중 비활성/검증 상태.
- **배지·칩:** 상태(예정/마감/참석/미정/거절), 필터 칩.
- **탭:** 세그먼트/언더라인 형태 중 하나로 통일.
- **바텀시트·모달:** 상단 라운드, dim 배경. 확인/취소 위계.
- **토스트/인라인 피드백:** 성공·실패 간단 알림.
- **리스트·카드:** 초대장 카드, 참석자 행, 알림 행, 댓글 등 반복 요소의 공통 규격.

### 공통 상태 (모든 데이터 화면에 적용)
- **로딩:** 스켈레톤 또는 간결한 로딩 표시(과한 스피너 금지).
- **빈 상태(Empty):** "데이터 없음" 금지. 일러스트/아이콘 + 짧은 안내 + 다음 행동 유도 버튼.
- **에러 상태:** 개발자 용어·에러코드 노출 금지. "잠시 후 다시 시도해 주세요" 같은 사람 말 + 재시도 버튼.
- **권한/차단 안내:** 막힌 이유를 부드럽게 설명(예: "호스트가 비공개로 설정한 초대장이에요").

## 5. 화면별 재디자인 명세 (전 화면 망라)

> 각 화면: **목적 / 반드시 보여줄 요소 / 주요 상태 / 주요 액션 / 감성 강조 여부**.
> **감성 강조(High)** = 브랜드 무드를 적극 표현(상세·템플릿·앨범·공유·온보딩). **시스템 UI(Calm)** = 깔끔·기능 중심(폼·설정·명단·어드민).

### 그룹 1. 인증 · 온보딩
| 화면 | 목적 | 반드시 보여줄 요소 | 주요 상태 | 주요 액션 | 감성 |
|---|---|---|---|---|---|
| **Splash** | 앱 진입·자동 로그인 시도 | 로고/브랜드, 로딩 표시 | 로딩 / 업데이트 안내 | — | High |
| **Login** | 소셜 로그인 | 브랜드 헤드라인, 소셜 버튼(카카오·네이버·구글·애플) | 기본 / 로그인 실패 | 소셜 로그인 | High |
| **Signup** | 회원가입 플로우 | 단계 표시(약관→닉네임→프로필), 입력 폼 | 단계별 / 검증 에러 | 다음 / 완료 | Calm |
| **Terms 동의** | 약관 동의 | 약관 목록(필수/선택), 전체동의 | 미동의 / 부분동의 | 동의하고 계속 | Calm |
| **Onboarding** | 신규 가이드 | 5단계 슬라이드 일러스트, 인디케이터, 권한 요청 | 단계별 | 다음 / 시작하기 | High |

### 그룹 2. 홈 · 목록
| 화면 | 목적 | 반드시 보여줄 요소 | 주요 상태 | 주요 액션 | 감성 |
|---|---|---|---|---|---|
| **Home(대시보드)** | 내 초대장 한눈에 | 인사말, 다가오는 모임 강조 카드, 예정/종료 구분, 만들기 진입 | 기본 / 빈 상태(초대장 없음) | 초대장 만들기 / 상세 보기 | High |
| **InvitationList** | 전체 목록·필터 | 탭(전체/주최/참여/종료), 초대장 카드 리스트, D-day | 기본 / 빈 상태 / 로딩 | 필터 전환 / 상세 보기 | Calm |
| **Calendar** | 달력으로 모임 보기 | 월 달력, 일정 점/마커, 선택일 모임 리스트 | 기본 / 일정 없는 날 | 날짜 선택 / 상세 보기 | Calm |

### 그룹 3. 초대장 상세 — 게스트
| 화면 | 목적 | 반드시 보여줄 요소 | 주요 상태 | 주요 액션 | 감성 |
|---|---|---|---|---|---|
| **Detail(Guest)** | 초대 확인·RSVP | **커버 이미지**, 제목, **날짜·장소(즉시 인지)**, 호스트, RSVP 버튼, D-day, 날씨 카드, 댓글·참석자·앨범 진입 | 미응답 / 응답완료 / 마감 / 비공개 | RSVP / 댓글 / 길찾기 | **High(최우선)** |

## 6. 화면 목업 출력 요구사항

- **프레임:** 390×844 세로. 각 화면을 모바일 디바이스 프레임 안에 렌더.
- **피델리티:** 하이파이(실제 서비스처럼). 회색 박스 와이어프레임 금지.
- **상태 변형:** §5의 "주요 상태"에 적힌 변형을 함께 보여줄 것(가능하면 같은 화면을 나란히).
- **카피:** 자연스러운 **한국어 더미 데이터**(실제 이름·날짜·장소·문구). 예: "정우의 집들이에 초대합니다", "2026년 6월 20일 토요일 오후 6시", "성수동 ○○ 카페".
- **주석:** 핵심 인터랙션·모션 의도는 짧은 라벨로 표기(예: "탭 시 바텀시트 등장").
- **일관성:** 모든 화면이 §3의 단일 디자인 시스템을 공유. 컴포넌트(버튼/카드/배지/입력)는 화면 간 동일.

## 7. 체크리스트 & 금지사항

### ✅ Do
- 화면당 **Primary 액션 1개**, 명확한 위계.
- **날짜·장소·CTA**를 스크롤 없이 보이게.
- 모든 반복 요소는 **공통 컴포넌트 규격** 준수(일관 radius·간격).
- **접근성**: 충분한 대비, 터치 타깃 44px+, 본문 14px+.
- 빈 상태/에러는 **사람 말 + 다음 행동 유도**.
- 감성 강조 화면(상세·템플릿·앨범·공유·온보딩)과 시스템 화면(폼·설정·명단·어드민)의 **밀도 차이**를 의도적으로.

### ❌ Don't
- 한 화면에 **Primary 버튼 여러 개**.
- **본문 12px 이하**, 흐린 배경 위 흐린 텍스트.
- **삭제·위험 액션을 주조색**으로(반드시 위험색).
- 빈 상태를 **"데이터 없음"** 한 줄로.
- **개발자 용어·에러코드**("UNAUTHORIZED" 등) 노출 → 사람 말로.
- 화면마다 **radius/색/폰트가 제각각**(시스템 불일치).
- 새 아이덴티티라는 이유로 **여러 무드를 한 앱에 혼용**.
